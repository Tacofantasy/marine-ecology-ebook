# Sa-Token 认证与权限设计

## 1. 目标与范围

本阶段为海洋生态数字电子书 Web 平台提供普通用户注册、账号登录、当前用户查询和管理员接口鉴权。认证框架采用 Sa-Token 的 Spring Boot 3 Starter 与无状态 JWT 模式，满足项目书中 JWT 无状态认证、角色分级和接口访问权限校验的要求。

本阶段只实现后端认证基础，不实现登录/注册页面、用户管理、找回密码、刷新令牌、强制下线、多端登录控制、通用 RBAC、Redis 会话存储或 Redis 业务缓存。用户管理阶段由管理员创建或提升管理员；Redis 在内容查询接口完成后，用于热点海洋图文内容缓存。

## 2. 角色与安全边界

平台角色固定为访客、`USER` 和 `ADMIN`：

- 访客可调用注册和登录接口。
- 通过注册创建的账号一律为 `USER`；请求体没有角色字段，服务端也不会读取或接受角色值。
- 首个管理员由数据库预置；后续管理员只能由已登录管理员在后续“用户管理”功能中创建或提升，当前演示管理员为数据库中的 `admin`。
- 注册接口拒绝用户名 `admin`，比较时忽略大小写，防止恶意用户抢注管理员名称。
- `users.status=0` 的账号不可登录；禁用后的既有 Token 是否立即失效不属于本期范围，Token 最长在两小时后自然过期。

管理员权限必须由后端验证。前端隐藏按钮或路由守卫只改善使用体验，不能替代接口鉴权。

## 3. 认证方案

引入 Sa-Token 1.45.0 的 `sa-token-spring-boot3-starter` 和 JWT 模块，配置无状态 JWT `StpLogic`。登录成功后以用户 ID 作为登录标识生成 Token；Token 名称为 `satoken`，客户端通过请求头 `satoken: <token>` 提交。

Token 固定有效期为 2 小时。JWT 签名密钥放在本机 `.env`，仓库只维护 `.env.example` 中的安全占位值；真实密钥不提交。单体开发环境不依赖 Redis，后续扩展为多实例或需要主动失效 Token 时，再将 Sa-Token 存储接入 Redis 并重新评估认证策略。

## 4. 接口契约

| 接口 | 请求 | 返回数据 | 访问规则 |
| --- | --- | --- | --- |
| `POST /api/auth/register` | 用户名、邮箱、密码 | 新注册用户的公开资料 | 仅创建启用的 `USER`；拒绝重复用户名、重复邮箱和保留用户名 `admin` |
| `POST /api/auth/login` | 用户名或邮箱、密码 | `token` 与当前用户公开资料 | 账号存在、启用且 BCrypt 密码匹配才登录成功 |
| `GET /api/auth/me` | 请求头 Token | 当前用户公开资料 | 必须已登录 |
| `GET /api/admin/auth-check` | 请求头 Token | 当前用户公开资料 | 必须已登录且角色为 `ADMIN` |

公开资料只包含 `id`、`username`、`email`、`role` 和 `status`；不返回 `password_hash` 或 JWT 签名密钥。

## 5. 组件与数据流

新增用户实体和 Mapper，使认证服务通过现有 `users` 表查询及写入账号。认证服务负责注册校验、BCrypt 密码哈希、密码比对和 Sa-Token 登录；控制器只负责请求校验和响应。

Sa-Token 拦截器放行健康检查和 `/api/auth/**`，其余需要保护的接口在控制器方法上显式校验登录或角色。角色信息从 `users.role` 查询，不从 Token 之外的前端输入读取。Sa-Token 的认证异常由全局异常处理转换为项目既有的统一响应：未登录或 Token 无效为 `40101`，登录但非管理员为 `40301`。

## 6. 错误处理

- 用户名、邮箱、密码格式不合格：`40001`。
- 用户名或邮箱重复、用户名为 `admin`：`40901`。
- 用户名或邮箱不存在、密码错误、账号被禁用：为避免泄露账号状态，统一返回登录失败的 `40001` 提示。
- 缺失、过期或无效 Token：`40101`。
- 非管理员访问管理员接口：`40301`。

不记录密码明文、Token 原文或 JWT 签名密钥到响应和业务日志。

## 7. 验证标准

1. 普通用户可以注册并登录；数据库中的密码为 BCrypt 哈希，角色固定为 `USER`。
2. 重复用户名/邮箱与任何大小写形式的 `admin` 注册均被拒绝。
3. 正确密码可得到 Token；错误密码和禁用账号无法登录。
4. `GET /api/auth/me` 对有效 Token 成功，对缺失/无效 Token 返回 `40101`。
5. 普通用户访问管理员验证接口返回 `40301`，预置管理员访问成功。
6. 在 Docker MySQL 启动的本地环境运行认证自动化测试及既有 API 基础设施测试，全部通过。

## 8. 后续衔接

分类、电子书和章节的后台写接口统一复用管理员鉴权；点赞和收藏接口统一复用登录鉴权。内容列表、详情和章节查询上线后，再在 Redis 中缓存热点资源并在内容修改/发布时清理相应缓存。
