# 分类与电子书管理 CRUD 修复设计

## 目标

修复分类管理与电子书管理中已确认的删除和验证缺陷，保持既有业务规则：二级分类只要仍关联任意电子书，便不可删除。修复范围不改变分类层级、发布条件或权限模型。

## 分类删除

`DELETE /api/admin/categories/{id}` 保持物理删除空分类的语义。

- 一级分类存在二级分类时，返回冲突错误。
- 二级分类关联任意状态的电子书时，返回冲突错误，不级联删除或迁移电子书。
- 空二级分类可成功删除。
- 管理端删除确认和错误反馈需明确说明该限制，避免将受保护的删除误报为系统故障。

## 电子书 CRUD

草稿电子书删除必须覆盖数据库中可能已存在的章节数据。

1. 在同一数据库事务内先删除该电子书的章节，再删除电子书记录。
2. 数据库提交成功后，再静默清理该电子书独占的封面文件；回滚时不删除原有封面。
3. 已发布电子书仍必须先撤回，才允许编辑、上传封面或删除。
4. 新建、更新、封面上传、发布、撤回、删除、分页和关键字筛选保持现有 API 形式。

## 输入与查询边界

- 电子书的分类筛选仅接受二级分类；一级分类或不存在分类返回参数错误，而不是返回误导性的空列表。
- 发布校验同时检查标题、简介上限与下限、封面、来源说明和非空章节，以防历史数据绕开 DTO 校验。

## 测试与验证

- 新增后端集成测试：空二级分类可删除；关联草稿或已发布电子书时删除被拒绝；含章节草稿电子书可删除且章节一并移除；分类筛选和发布边界正确返回业务错误。
- 为集成测试提供可重复的 MySQL/Redis 启动前置条件或隔离配置，避免测试套件在数据库不可用时产生无效结果。
- 前端进行生产构建验证，并人工核验管理端的新增、编辑、封面替换、撤回、删除和分类删除提示。

## 非目标

- 不支持删除含电子书的分类。
- 不自动迁移电子书分类。
- 不实现章节编辑或电子书阅读功能。
