# 前端认证可视化联调设计

## 目标与范围

本迭代完成首次浏览器端到端联调：访客可以注册、登录，前端保存登录状态，并通过受保护路由验证当前用户接口。范围仅限认证界面与其所需的前端基础能力；不实现分类、电子书、收藏、点赞或后台内容管理。

## 技术边界

- 在既有 Vue 3、TypeScript、Vite 工程中增加 Vue Router。
- 不引入 Pinia 或额外 HTTP 客户端库。认证状态由一个轻量组合式模块管理，请求继续使用原生 `fetch`。
- Token 使用 `localStorage` 保存，请求头名称固定为 `satoken`，与后端接口文档一致。
- 本轮不实现刷新 Token、记住登录、找回密码或管理员后台页面。

## 路由与页面

| 路径 | 访问规则 | 页面职责 |
| --- | --- | --- |
| `/` | 公开 | 显示现有平台首页；已登录时显示用户名、角色与退出登录入口。 |
| `/login` | 仅访客 | 提交账号和密码到 `POST /api/auth/login`；成功后保存认证资料并返回首页。 |
| `/register` | 仅访客 | 提交用户名、邮箱和密码到 `POST /api/auth/register`；成功后跳转登录页。 |
| `/profile` | 需要登录 | 调用 `GET /api/auth/me` 并显示当前用户公开资料，用于验证路由守卫和请求头传递。 |

已登录用户访问 `/login` 或 `/register` 时跳转首页；未登录用户访问 `/profile` 时跳转 `/login`，并携带原始目标地址以便登录成功后返回。

## 数据流与错误处理

1. 登录成功后，将 `token` 与用户公开资料写入 `localStorage`，并在内存中同步认证状态。
2. 统一 API 方法会为需要认证的请求附加 `satoken` 请求头。
3. 应用启动时从本地恢复认证状态；访问 `/profile` 时以 `/api/auth/me` 的响应作为最终身份校验。
4. 接口响应业务码 `40101` 时，清除本地认证资料并跳转登录页；其他非成功响应在当前表单附近显示后端返回的安全提示。
5. 退出登录只清除本地认证资料；当前后端没有注销接口，因此不向服务端发请求。

## 验收标准

- 浏览器中可完成注册、登录和退出，登录成功后首页显示用户名与角色。
- 登录请求携带账号和密码；之后访问 `/profile` 的请求携带 `satoken` 头，并能显示后端返回的用户资料。
- 无 Token 直接访问 `/profile` 会跳转 `/login`；登录后返回原目标页面。
- Token 无效或过期时，前端清除登录状态并回到登录页。
- 注册 `admin` 或重复账号时，页面显示后端的错误提示，不伪造成功状态。
- `npm run build` 通过，并以本地 Docker MySQL 中的认证后端完成一次人工浏览器联调。
