# 数据库基础层设计

## 1. 目标与范围

本阶段为海洋生态数字电子书 Web 平台建立可重复的 MySQL 8 开发环境和版本化数据库结构。完成后，任意成员可在空环境启动本地 MySQL，并由后端自动创建相同的基础表和演示数据。

本阶段只包含 Docker MySQL、后端数据库连接、MyBatis-Plus、Flyway 迁移脚本和最少的初始数据。不包含登录、JWT、业务接口、管理页面、Redis、云数据库或生产服务器部署。

## 2. 本地环境

项目根目录提供 `compose.yaml`，其中仅定义 `mysql` 服务：

- 使用 MySQL 8 镜像与命名 volume 保存数据；重启容器不会丢失数据。
- 默认端口映射为本机 `3307`，避免与已有 MySQL 冲突；可在本机 `.env` 调整，供 Spring Boot 在开发时连接。
- 仓库提交 `.env.example`，列出数据库名、用户名和端口等非敏感配置；每位成员在本机复制为 `.env` 并设置自己的密码，`.env` 不进入 Git。
- 成员通过 `docker compose up -d mysql` 启动自己的数据库实例。后续共享测试环境复用同一 Compose 思路，但不在本阶段实施。

## 3. 后端与迁移

后端增加 MySQL JDBC 驱动、MyBatis-Plus 和 Flyway。`application.yml` 从环境变量读取本地数据库连接参数，并只为本地开发提供默认的非敏感值；密码不写入版本库。

Flyway 迁移脚本位于 `backend/src/main/resources/db/migration/`，按 `V1__...sql` 的单向版本序列执行。应用启动时，Flyway 先创建并记录迁移版本，再由后续 MyBatis-Plus 业务代码访问表。已发布的迁移脚本不修改；表结构调整必须新增下一个版本脚本。

## 4. 数据模型

首个迁移版本创建以下表及必要索引、外键和唯一约束：

| 表 | 用途 | 核心约束 |
| --- | --- | --- |
| `users` | 注册用户和管理员 | 用户名、邮箱唯一；角色仅 `ADMIN` 或 `USER` |
| `categories` | 多级分类 | `parent_id` 指向同表；排序和发布状态 |
| `ebooks` | 电子书元数据 | 必属一个分类；含阅读量和来源说明 |
| `chapters` | 富文本章节 | 必属一本电子书；电子书内排序唯一 |
| `tags` | 可复用主题标签 | 标签名唯一 |
| `ebook_tags` | 电子书—标签关联 | `(ebook_id, tag_id)` 唯一 |
| `favorites` | 用户收藏 | `(user_id, ebook_id)` 唯一 |
| `likes` | 用户点赞 | `(user_id, ebook_id)` 唯一 |

各表使用 `BIGINT` 主键、`created_at` 与 `updated_at` 时间字段。状态字段只服务首期草稿/发布或启用/禁用需求，不引入通用工作流。章节正文和来源说明使用支持 UTF-8 的 `TEXT` 字段。演示数据包括一个密码哈希形式的管理员、公开分类、一本电子书及其章节；不包含来源不明的实际素材。

## 5. 错误处理与边界

数据库不可用或迁移失败时，应用启动失败并在日志中保留底层原因；不提供绕过迁移继续运行的模式。未来业务接口发生数据完整性冲突时，由业务层转换为项目既有统一响应结构；本阶段不新增业务接口。

Docker MySQL 仅绑定给本机开发，不能作为公共生产数据库。真实密码和数据库数据 volume 不提交到 Git。

## 6. 验证标准

1. 从无数据库的本机环境执行 Compose 启动命令后，MySQL 健康可用。
2. 后端启动时，Flyway 创建全部首期表、索引和演示数据；重复启动不重复执行迁移。
3. 现有健康检查和 API 基础设施的自动化测试全部通过。
4. 数据库迁移说明、启动命令和默认账号（仅演示数据）写入项目文档，其他成员可按说明复现。

## 7. 后续衔接

下一阶段的登录与 JWT 直接使用 `users` 表；分类、电子书与章节管理复用内容表；收藏和点赞接口复用对应唯一约束。共享 Linux 测试环境与 Nginx 部署留到功能完成后的部署阶段。
