# 海洋生态数字电子书 Web 端实施计划

> 依据已确认的《Web 端设计规格》执行。首期只建设 Web 平台，不编写嵌入式、TCP、语音或端侧大模型代码。

## 0. 完成标准

- `develop` 分支能够从零启动前端、后端、MySQL，并通过健康检查。
- 三类访问身份符合约定：访客只读已发布内容，用户可点赞/收藏，管理员可管理和查看统计。
- 内容可按“分类 → 电子书 → 章节”维护、发布和阅读，电子书与章节均可记录来源说明。
- 项目可通过 Docker Compose 与 Nginx 在 Linux 测试环境部署。
- 每个合并功能都附带可复现的验证记录；最终没有阻断演示的缺陷。

## 1. 仓库与本地环境（第 1—2 天）

### 1.1 建立忽略规则与目录

新增 `.gitignore`，忽略 IDE 文件、构建目录、`node_modules`、前端产物、后端 `target`、本地环境文件、项目私有工具目录和上传文件。创建下列目录：

```text
frontend/                         # 单个 Vue 3 工程
backend/                          # 单体 Spring Boot 工程
docs/api/                         # 接口契约与联调记录
docs/database/                    # ER 图、迁移说明与种子数据说明
docs/testing/                     # 测试用例、缺陷与测试报告
deploy/                           # Docker Compose、Nginx、部署说明
scripts/                          # 项目本地辅助脚本
```

### 1.2 固定项目工具链

- 将项目私有 Temurin JDK 17 放入 `.tools/jdk17/`，不修改系统 `JAVA_HOME`，不影响其他项目的 JDK 21。
- 提供 `scripts/use-jdk17.ps1`：仅在执行该脚本启动的命令进程中设置 `JAVA_HOME` 与 `PATH`。
- 使用 Maven Wrapper 或明确记录 Maven 3.9.x 版本；前端使用当前稳定 Node.js 与 npm。
- 在 `README.md` 列出一套 Windows 本地启动命令及对应的验收输出。

### 1.3 骨架验收

1. Spring Boot 启动 `/api/health`，返回统一成功结构与应用状态。
2. Vue 3 启动后显示“海洋生态数字电子书”基础页面。
3. Vite 将 `/api` 代理至后端；前端首页调用健康检查并展示“服务连接正常”。
4. MySQL 连接参数放进不提交的本地环境文件；首次启动可执行 Flyway 数据库迁移。

## 2. 后端基础能力（第 3—5 天）

### 2.1 工程约定

在 `backend/src/main/java/...` 中按 `common`、`auth`、`content`、`interaction`、`dashboard` 模块组织。每个模块分出 `controller`、`service`、`mapper`、`entity`、`dto` 与 `vo`；不为首期目标引入微服务或通用权限引擎。

- 统一响应：`code`、`message`、`data`、`timestamp`。
- 统一异常处理：参数校验、未认证、无权限、资源不存在、业务冲突与系统异常。
- 使用 Bean Validation 校验请求参数；密码只存 BCrypt 哈希。
- 使用 MyBatis-Plus 处理基础 CRUD，复杂统计保留显式 SQL。
- Swagger/OpenAPI 仅在开发环境开放，接口上写明认证要求、请求字段与错误码。

### 2.2 首期数据库迁移

使用按版本编号的 Flyway SQL 文件建立：

- `users`：账号唯一索引、密码哈希、`ADMIN/USER`、状态、创建/更新时间。
- `categories`：名称、`parent_id`、排序、状态与时间字段。
- `ebooks`：分类、标题、封面 URL、简介、发布状态、阅读量、来源说明与时间字段。
- `chapters`：电子书、标题、富文本正文、排序、发布状态、来源说明与时间字段。
- `tags`、`ebook_tags`：标签与电子书关联。
- `favorites`、`likes`：用户与电子书关联，均在 `(user_id, ebook_id)` 上建立唯一约束。

同时加入最少量可演示种子数据：一个管理员、一个普通用户、若干分类、至少一本带公开/自制来源说明的电子书和章节。种子账户的默认密码只写入本地开发说明，部署前必须修改。

### 2.3 认证与权限

实现 `POST /api/auth/register`、`POST /api/auth/login` 和 `GET /api/auth/me`。

- 登录成功返回短期 JWT 与当前用户资料。
- JWT 过滤器解析用户身份，管理员接口统一要求 `ADMIN`。
- 公开内容查询不要求 Token；互动接口要求 `USER` 或 `ADMIN` 的有效 Token。
- 返回 401 或 403 时保持准确区分，不能以“前端隐藏按钮”替代后端鉴权。

验证：注册、登录、错误密码、缺失 Token、普通用户访问管理员接口、管理员正常访问均覆盖自动化或 API 测试。

## 3. 内容后台（第 5—10 天）

### 3.1 分类管理

- 公开接口只返回已启用分类树。
- 管理端支持新增、编辑、排序、启用/停用和删除前的关联检查。
- 防止分类成为自身或后代的父节点；删除有电子书的分类时给出明确业务错误。

### 3.2 电子书管理

- 管理端可分页查询、新增、编辑、删除、设置分类、标签、封面、简介、来源说明与草稿/发布状态。
- 公开详情仅返回已发布电子书；公开列表支持分类、关键字和标签筛选。
- 发布前校验标题、分类、来源说明及至少一个可发布章节。

### 3.3 章节编辑与发布

- 管理端可维护章节标题、富文本正文、顺序、来源说明和草稿/发布状态。
- 使用受控富文本编辑器，提交前清理危险 HTML；阅读页按安全白名单渲染。
- 同一电子书内排序稳定；调整排序后公开目录顺序一致。
- 阅读接口只允许获取已发布电子书下的已发布章节。

验证：后台以管理员身份完成“创建分类 → 新建电子书 → 添加章节 → 发布 → 用户端可见”的完整闭环。

## 4. 用户端（第 10—13 天）

### 4.1 Vue 工程结构

```text
src/
  portal/       # 首页、分类、详情、目录、阅读、登录注册
  admin/        # 概览、分类管理、电子书管理、章节编辑
  shared/       # API 客户端、类型、路由守卫、布局、状态、通用组件
```

路由使用 `meta.requiresAuth` 与 `meta.requiresAdmin`；守卫只负责体验，真实权限由后端接口校验。Axios 拦截器附带 JWT，遇到失效 Token 清理本地会话并提示重新登录。

### 4.2 用户流程

1. 首页展示海洋主题入口、推荐分类与已发布电子书。
2. 分类页显示分类树和电子书列表；支持空态、加载态与错误重试。
3. 详情页显示封面、简介、标签、来源说明、目录、阅读量及互动状态。
4. 阅读页显示章节正文与目录跳转；打开已发布章节时触发一次阅读量记录。
5. 未登录点击点赞/收藏时引导登录；登录后可切换状态，重复操作不会产生重复记录。

## 5. 管理端与统计（第 13—15 天）

### 5.1 管理端页面

- 登录后显示侧边栏和当前身份；非管理员不可进入后台路由。
- 数据概览显示电子书数、已发布电子书数、章节数、用户数、累计阅读量、点赞数与收藏数。
- 分类、电子书、章节列表均有分页、明确操作反馈、删除二次确认与空态。
- 章节编辑页在离开未保存内容前提示确认；发布动作反馈发布结果。

### 5.2 统计接口

实现只读 `GET /api/dashboard/overview`，只对管理员开放。统计以数据库真实数据聚合；不为了展示图表加入缓存、消息队列或实时推送。若时间允许，可在前端以图表展示分类分布或热门电子书，但不影响基础验收。

## 6. 测试、部署与归档（第 16—20 天）

### 6.1 测试

将测试用例写入 `docs/testing/`，至少覆盖：

- 注册、登录与 Token 失效。
- 访客/用户/管理员三种权限边界。
- 分类、电子书、章节的增删改查、排序和发布状态。
- 点赞、收藏的幂等性与唯一约束。
- 富文本安全过滤及来源说明校验。
- 公开端只读取已发布内容。
- 异常提示、空态、常见桌面与移动视口的可用性。

记录缺陷编号、复现步骤、修复分支与回归结果。性能测试不预设 TPS；若执行 JMeter，则记录机器配置、数据量、并发、持续时间、接口和结果。

### 6.2 Docker 部署

- `backend/Dockerfile` 产出后端镜像；`frontend` 使用构建阶段产出静态文件。
- `deploy/docker-compose.yml` 编排 MySQL、后端、Nginx；敏感配置通过服务器环境变量注入，不提交密码。
- Nginx 托管前端、将 `/api` 代理至后端，并配置 SPA 刷新回退。
- 部署演练从空环境执行：启动服务、迁移数据、访问首页、管理员登录、创建内容、用户阅读与互动。

### 6.3 发布与分支

每项开发从 `develop` 创建 `feature/<module>`，自测通过且接口文档同步后，由至少一名成员审查并合并至 `develop`。第 19—20 天完成回归后，从 `develop` 合并稳定版本到 `main` 并打版本标签。任何人不得直接向 `main` 提交业务代码。

## 7. 当前第一迭代的具体任务

按以下顺序实现并在每一步验证：

1. 安装项目私有 JDK 17，加入 `.gitignore` 与 JDK 启动脚本。
2. 初始化 `backend`，实现健康检查、统一响应和本地配置模板。
3. 初始化 `frontend`，配置 Vite `/api` 代理，显示并验证健康检查结果。
4. 连接 MySQL，加入第一版 Flyway 迁移与演示种子数据。
5. 写 README 的从零启动步骤，确保组内任意成员可复现。

这一迭代验收后，才进入 JWT 与内容管理功能开发。
