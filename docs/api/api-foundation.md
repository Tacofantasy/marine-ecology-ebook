# 接口通用约定

所有 Web API 均返回下列 JSON 结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-08-27T03:32:30Z"
}
```

- `code`：前后端约定的业务码。`0` 表示成功。
- `message`：可直接向用户展示的简短提示。
- `data`：成功时的业务数据；失败时为 `null`。
- `timestamp`：后端生成响应的 UTC 时间。

HTTP 状态码用于表示请求层面的结果，`code` 用于前端精确处理业务结果。两者必须保持一致。

| 业务码 | HTTP 状态 | 含义 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 40001 | 400 | 参数错误或校验不通过 |
| 40101 | 401 | 未登录或登录已失效（认证模块接入后启用） |
| 40301 | 403 | 无权限（认证模块接入后启用） |
| 40401 | 404 | 请求的业务资源不存在 |
| 40901 | 409 | 当前资源状态不允许该操作 |
| 50000 | 500 | 未预期系统异常；不向前端返回内部错误详情 |

业务代码可抛出 `BusinessException` 并指定 `ResultCode`。参数校验和未知异常由 `GlobalExceptionHandler` 统一转换，无需在 Controller 中重复 `try/catch`。
