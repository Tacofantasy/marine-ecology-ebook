frontrnd# 海洋生态数字电子书 Web 端开发计划

## 1. 目标与范围

本计划用于 5 人实训小组在 20 个工作日内完成可演示、可部署、可验收的海洋生态数字电子书 Web 平台。系统采用前后端分离架构：Vue 3 + Vite 单工程前端、Spring Boot 单体后端、MySQL 与 Redis；前端通过 REST API 与 WebSocket 接入后端，嵌入式终端暂不实施。

V1 交付前台浏览与阅读、注册登录、点赞、后台内容管理、用户管理、统计报表、实时点赞通知以及 Docker 部署。不包含收藏、嵌入式端接入和复杂通用 RBAC。

## 2. 已确认的业务与技术基线

### 2.1 用户与权限

| 身份 | 可做事项 |
| --- | --- |
| 访客 | 浏览已发布电子书、阅读章节、查看统计；点击点赞时跳转登录/注册。 |
| 注册用户 | 具有访客全部浏览能力；每篇章节文档仅可点赞一次。 |
| 子管理员（ADMIN） | 管理电子书、分类、章节文档和注册用户；不可管理任何管理员账号。 |
| 总管理员（SUPER_ADMIN） | 拥有子管理员能力，并可创建、禁用、注销和重置子管理员密码。 |

- 公开注册仅创建注册用户；用户名为 `admin` 或类似名称不授予管理员权限。
- 首次总管理员：开发环境由初始化配置创建；生产环境首次启动时从环境变量读取登录名与强密码创建，之后不覆盖。
- 用户和管理员均为逻辑删除。注销后不可登录、不出现在常规列表，但点赞记录与统计继续保留；系统始终至少保留一名启用的总管理员。
- 登录名唯一且注册后不可修改；昵称用于页面展示且可修改；邮箱为可选联系方式。

### 2.2 内容与发布

- 内容层级固定为“一级分类 → 二级分类 → 电子书 → 章节文档”；V1 不允许第三级分类，电子书必须归属二级分类。
- 分类删除保护：一级分类存在二级分类、二级分类存在电子书时均禁止删除。
- 电子书删除采用二次确认，并在同一事务内删除其章节文档和正文；封面仅在确认无引用后清理。
- 电子书有 `DRAFT`（草稿）和 `PUBLISHED`（已发布）状态。仅已发布电子书对前台可见。
- 发布前必须已有二级分类、名称、封面、内容来源说明，以及至少一篇正文非空的章节；删除已发布书籍的最后一篇章节后，电子书自动退回草稿。
- 电子书层面必须填写内容来源说明；章节使用不同来源的资料时填写章节来源补充。
- 文档删除递归删除其子孙文档及正文，事务内完成，并在确认提示中列出受影响章节。

### 2.3 互动、统计与通知

- 点赞必须登录；以数据库 `document_like(user_id, document_id)` 唯一约束保证同一用户对同一章节只能点赞一次。
- 阅读量按主体和章节去重：同一已登录用户或访客 IP 哈希在 30 分钟内仅计一次，Redis 保存防重窗口。
- 每 5 分钟汇总电子书下的章节数量、阅读量与点赞量；每天 00:05（中国标准时间）生成统计快照；首页展示累计数据、当日数据与近 30 天趋势。
- 点赞成功后通过 WebSocket 向在线的已登录用户广播不包含点赞者个人信息的公共通知。

### 2.4 安全与接口

- 认证采用 Sa-Token + Redis 会话。浏览器将请求凭证保存至 `sessionStorage`，请求头名称为 `satoken`，会话有效期 24 小时。
- 密码使用 BCrypt 哈希存储；不采用 MD5。管理接口在后端实施角色校验，前端路由守卫仅改善体验，不能替代后端鉴权。
- 接口统一返回 `{ code, message, data, timestamp }`，成功业务码为 `0`；分页 `data` 统一为 `{ total, list }`。
- 封面保存至 `uploads/covers/`，正文图片保存至 `uploads/content/`；数据库和富文本只保存相对访问路径，Nginx 对外提供 `/uploads/` 静态访问。

### 2.5 前端与部署

- Vue 3 + Vite 保持不变；全站引入 Ant Design Vue 的布局和交互组件，并通过主题令牌与自定义 CSS 保留海洋主题。
- 前端和后端分别构建；生产环境以 Docker Compose 运行 Nginx、前端静态资源、后端、MySQL、Redis，并将 `uploads/` 配置为持久化挂载卷。

## 3. 数据与模块拆分

| 模块 | 核心表或数据 | 主要能力 |
| --- | --- | --- |
| 用户与认证 | `user`、Redis 登录会话 | 注册、登录、退出、个人资料、总管理员/子管理员鉴权、逻辑注销。 |
| 分类 | `category` | 固定两级分类、排序、引用保护、前台树菜单。 |
| 电子书 | `ebook` | 草稿/发布、封面上传、来源说明、分页与分类查询、级联删除。 |
| 文档 | `document`、`content` | 树形章节、富文本编辑、正文图片上传、事务保存、递归删除、前台阅读。 |
| 互动 | `document_like`、Redis 阅读窗口 | 登录点赞、唯一防重、阅读计数。 |
| 统计 | `ebook_snapshot` | 定时汇总、每日快照、首页卡片、30 天趋势图。 |
| 通知 | WebSocket 会话 | 已登录用户的点赞公共通知。 |

## 4. 开发顺序与里程碑

### 阶段 0：基线整理（第 1–2 天）

1. 从 `develop` 创建功能分支，核对现有认证、统一响应、全局异常与 Flyway 基础设施。
2. 将现有无状态 JWT 登录改为 Redis 会话；前端由 `localStorage` 改为 `sessionStorage`。
3. 增加 `SUPER_ADMIN`、`ADMIN`、`USER` 与账号状态、登录名、昵称等迁移；实现首次总管理员初始化。
4. 完成 Ant Design Vue 接入和已有登录/注册/个人页的视觉迁移。

**完成标准**：注册用户无后台权限；总管理员和子管理员边界经接口测试验证；刷新页面保持登录、注销后 Token 立即失效。

### 阶段 1：分类与电子书管理（第 3–6 天）

1. 创建分类、电子书、封面上传和来源说明相关迁移及实体、DTO、Mapper、Service、Controller。
2. 实现两级分类树、排序、删除保护和前台分类查询。
3. 实现电子书后台分页、搜索、新增、编辑、草稿/发布、封面上传、删除及发布完整性校验。
4. 实现前台欢迎页、二级分类筛选、电子书卡片和分页。

**完成标准**：只能发布完整电子书；未发布内容不能从前台接口读取；上传文件在容器重建后仍可访问。

### 阶段 2：章节与在线阅读（第 7–10 天）

1. 创建章节文档和正文表，实施父子树校验、文档与正文事务保存、递归删除。
2. 集成富文本编辑器，支持拖拽上传正文图片、内容回显和抽屉预览。
3. 实现阅读页：电子书目录树、首篇自动选中、章节切换、富文本自适应展示。
4. 实现阅读量 Redis 30 分钟防重及章节/电子书计数更新。

**完成标准**：不能将章节移动到自身或子孙节点下；删除父章节不会遗留正文；移动端和桌面端图片不溢出。

### 阶段 3：点赞、用户与通知（第 11–13 天）

1. 创建点赞记录表及唯一索引，实现登录点赞、重复提示和计数更新。
2. 访客点击点赞跳转登录/注册，登录后返回原阅读页并提示再次点击，不自动执行点赞。
3. 实现用户个人资料、普通用户逻辑注销；实现总管理员对子管理员的创建、禁用、注销和密码重置。
4. 配置 WebSocket，仅为已登录用户建立连接；异步广播匿名化点赞通知。

**完成标准**：并发重复点赞只成功一次；子管理员无法管理管理员账号；已注销账号无法使用旧会话继续访问。

### 阶段 4：统计报表与后台完善（第 14–16 天）

1. 实现电子书统计聚合任务与每日快照任务，编写可重复执行的 SQL 与任务测试。
2. 实现首页累计/当日统计卡片、预计阅读量和近 30 天 ECharts 趋势图，支持导出图片。
3. 完善后台用户、分类、电子书、文档页面的分页、搜索、删除确认、空状态、加载态与错误提示。

**完成标准**：快照重复执行不产生重复记录；趋势数据、阅读量、点赞量能与明细数据核对一致。

### 阶段 5：联调、部署与验收（第 17–20 天）

1. 执行前后端接口联调、权限回归、异常与文件上传边界测试。
2. 编写 `docker-compose.yml`、Nginx 配置、生产环境变量示例、数据库备份与恢复说明。
3. 部署至 Linux 测试服务器，验证 HTTPS/反向代理（如服务器具备证书）、持久化上传目录、MySQL/Redis 重启恢复。
4. 准备测试用例、接口文档、部署手册、答辩数据和演示脚本。

**完成标准**：新机器按文档可启动；演示路径覆盖游客浏览、注册登录、管理员内容发布、阅读点赞、通知、统计与权限拦截。

## 6. 测试与验收清单

1. 认证：无 Token、过期 Token、注销 Token、被禁用账号、普通用户访问后台、子管理员管理管理员均被正确拒绝。
2. 数据完整性：分类删除保护、电子书发布门槛、章节树循环保护、文档/正文事务、点赞唯一约束、逻辑注销保留统计。
3. 文件：非法类型、超限文件、路径穿越、容器重启后的封面与正文图片访问。
4. 前台：访客浏览、登录回跳、阅读防重、点赞提示、WebSocket 通知、移动端富文本展示。
5. 后台：四类管理操作、分页/搜索、草稿与发布、删除确认、权限边界。
6. 统计：汇总任务幂等、每日快照唯一、30 天趋势和数据导出。
7. 部署：全新环境启动、环境变量缺失提示、数据库和 Redis 重启恢复、上传卷持久化。

## 7. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 富文本带来 XSS | 后端对 HTML 做白名单净化；前端仅渲染已净化内容。 |
| 上传文件丢失或被伪造 | 后端校验真实类型、大小和文件名；使用持久化卷与 Nginx 静态映射。 |
| 权限绕过 | 后端 Sa-Token 注解/拦截器为唯一权限依据；每个管理接口添加权限测试。 |
| 并发重复点赞 | 数据库唯一索引为最终防线，事务中更新计数。 |
| 统计不一致 | 明细数据为事实来源；定时汇总和快照任务幂等、可重跑。 |
| 五人并行冲突 | 模块化分支、PR 审查、迁移文件顺序编号和接口契约先行。 |
